# Drill Down

The user decides. Your job is to find every open question and have the
user answer it. The subject, the scope, the level of detail, and what
happens afterwards come from the context.

1. Restate what you were given and get the user to confirm it.
2. Learn what you can from the code and the documents. Do not ask what
   they already answer.
3. List every open question. Put first the questions that could change
   everything or show the work is impossible. Show the list.
4. Ask one question per turn, with the options and your recommended
   answer. After each answer:
   - add a question for each new ambiguity or contradiction, including
     finer questions the answer raises
   - drop questions that no longer apply
   - treat a vague answer as open, and propose a concrete one
5. When the list is empty, walk through the work step by step. Any step
   you are unsure of is a new question.

If an answer contradicts an earlier one, resolve the contradiction before
going on.

If the work cannot be done, say why, and what would have to change.

If the user stops early, propose an assumption for each open question and
mark the accepted ones as assumptions.

End by listing the decisions and the assumptions.
